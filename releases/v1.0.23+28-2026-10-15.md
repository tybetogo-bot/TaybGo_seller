# TaybGo Seller 1.0.23+28

Release date: 15 October 2026.

- Restaurant promotions: upload images using the menu's existing Cloudinary flow, submit for review, view feedback, and publish or pause approved promotions.
- An animated unread notification count, accessible labels, reduced-motion support, and clearer notification visibility.
- Session-bound request handling and account data: logout unregisters push devices, revokes the session, clears delivered notifications, and prevents old requests from updating a new account.
- Production Places configuration is required by both store build scripts. The current changelog also restores the missing 1.0.22+27 iOS release notes.

## Store packages

Production API: `https://taybgo.com`. Android application ID and iOS bundle ID: `com.taybgo.seller`. Firebase project: `sellertaybgo`.

iOS uses version 1.0.23, build 28. The Android AAB uses version 1.0.23, version code 4028, above the previous per-ABI APK codes (up to 4024). The app's displayed release label remains 1.0.23+28 on both platforms.

Use a private, ignored JSON file containing `ENV=prod` and `GOOGLE_MAPS_API_KEY`. Never commit that file or its key.

```sh
sh scripts/release/build_aab.sh /private/path/release-defines.json
sh scripts/ios/build_release.sh /private/path/release-defines.json /private/path/ExportOptions.plist
python3 scripts/ios/validate_ipa.py /path/seller.ipa --version 1.0.23 --build 28 --report /path/ipa-validation.json
```

## Verification and distribution

The feature suite passed 95 tests before release packaging. Production web review confirmed the authenticated promotions list and existing approved promotion without changing production promotions. Mocked tests cover uploads, approval rules, pagination, account changes, unread-badge motion and session cleanup.

Store packaging must additionally verify release signatures, native version metadata, the compiled Places key, Firebase identity, notification permissions/channels, bundled sounds, and iOS production APNs entitlements. Local reports accompany the build artifacts.

Physical-device push delivery, notification taps, foreground/background playback and Places interaction require device QA. Store build-number availability and store processing remain unverified. This release preparation does not upload, publish, or deploy the app.
