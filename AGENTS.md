# AGENTS.md

## Project Overview

TaybGo Seller is a Flutter app for restaurant owners/sellers to manage their restaurants, menus, orders, and coupons on the TaybGo platform. Targets Android, iOS, and Web.

## Build & Run

```bash
# Install dependencies
flutter pub get

# Code generation (freezed, json_serializable, riverpod)
dart run build_runner build --delete-conflicting-outputs

# Run dev flavor
flutter run --flavor dev -t lib/main_dev.dart --dart-define=ENV=dev

# Run prod flavor
flutter run --flavor prod -t lib/main_prod.dart --dart-define=ENV=prod

# Run web (no --flavor)
flutter run -d chrome -t lib/main_dev.dart --dart-define=ENV=dev

# Build prod APK
flutter build apk --flavor prod -t lib/main_prod.dart --dart-define=ENV=prod --split-per-abi --release
```

## Flavor System

- **ENV dart-define** controls Dart-side config (API URL, app name, logging) via `EnvConfig` in `lib/core/config/env_config.dart`
- **Android product flavors** (`dev`/`prod`) in `android/app/build.gradle.kts` control native app name and application ID suffix
- Entry points: `lib/main_dev.dart` and `lib/main_prod.dart` (both delegate to `lib/main.dart`)
- Dev API: `https://dev.taybgo.com` | Prod API: `https://taybat-backend-dev.onrender.com`

## Architecture

- **State Management**: Riverpod with code generation (`@riverpod` annotations)
- **Navigation**: GoRouter (`lib/app/router/`)
- **Networking**: Dio with auth/retry/error interceptors (`lib/core/network/`)
- **Feature-based structure**: Each feature in `lib/features/` has its own `data/`, `application/`, and `presentation/` layers
- **Code generation**: freezed for models, json_serializable for JSON, riverpod_generator for providers

## Key Directories

- `lib/core/config/` - App config, environment config, constants
- `lib/core/network/` - API client, interceptors (auth, retry, error)
- `lib/core/providers/` - Global Riverpod providers
- `lib/features/` - Feature modules (auth, orders, menu, restaurant, etc.)
- `lib/shared/` - Shared UI widgets
- `packages/phone_otp_auth_ui/` - Local package for phone OTP auth UI

## Conventions

- Use `AppConfig` for app-level settings, `EnvConfig` for environment-specific values
- API endpoints are defined in `ApiEndpoints` class in `lib/core/config/constants.dart`
- All API calls go through the Dio instance from `ApiClient.getInstance()`
- Storage keys are centralized in `StorageKeys` class
- Translations use a custom `TranslationService` with JSON files in `assets/translations/`

## Firebase

- Project ID: `sellertaybgo`
- Web hosting: `sellertaybgo.web.app`
- Config: `lib/firebase_options.dart` (generated by FlutterFire CLI)
- Android: `android/app/google-services.json`

## Common Tasks

- **Add a new API endpoint**: Add to `ApiEndpoints` in `lib/core/config/constants.dart`
- **Add a new feature**: Create a directory under `lib/features/` with `data/`, `application/`, `presentation/` subdirectories
- **Change environment URLs**: Edit `lib/core/config/env_config.dart`
- **Regenerate code**: `dart run build_runner build --delete-conflicting-outputs`
- **Deploy web**: `flutter build web --release --no-wasm-dry-run -t lib/main_prod.dart --dart-define=ENV=prod && firebase deploy --only hosting`

## Rescue Deals

- Feature: `lib/features/rescue_deals/`, entered from Profile settings; routes and endpoints are centralized as usual.
- Backend contract and screenshots: `docs/rescue-deals.md`. Backend PR #91 and its migrations must be deployed before frontend release.
- Prices use integer cents in the rescue flow; sends decimal strings and UTC dates. Do not send original-price snapshots or directly overwrite remaining inventory.
- Stock adjustments retain an account/restaurant/deal-scoped idempotency key in SharedPreferences until their outcome is known. Never replace an unresolved adjustment with a new key.
- Gate late responses and form/sheet actions on both the session generation and selected restaurant. Archive only when the backend provides the archival contract; old DELETE behavior removed records.
- Preserve rescue IDs and saved prices through order details and edits. Keep ordinary and rescue lines for the same menu item distinct.
